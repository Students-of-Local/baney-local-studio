# Linux Local Studio Application

- Rust + GTK4 + libadwaita. Links `core/` (`local-studio-core`) as a plain crate: no UniFFI, no C ABI.
- `linux/` is its own Cargo workspace (own `Cargo.lock`), outside the root one, so `cargo clippy --workspace` on macOS never needs GTK. The core's Eukhe dependencies (the release tag pinned in the root `Cargo.toml`) resolve from the root.
- Dev shell (Rust 1.98.1, Zig 0.15 for the core's libghostty-vt, GTK 4.22, libadwaita 1.9, WebKitGTK 6, GStreamer for notification sounds, clang, xvfb-run, dbus, fonts, icons): `nix develop ./linux` in a git checkout, `nix develop path:linux` in a plain copy. Run the commands below from `linux/` inside it. Point `ZIG_GLOBAL_CACHE_DIR` at a scratch directory on shared machines. On x86_64 the shell links with the Nix-wrapped system linker (`-Clinker-features=-lld`) instead of Rust's bundled LLD, which would drop the store library paths from the binary's runpath.
- Build: `cargo build` → `target/debug/local-studio`.
- Lint: `cargo clippy --all-targets -- -D warnings` and `cargo fmt --check`. Same bar as the rest: no `unsafe`, `unwrap`, `expect` or code comments.
- Daemon: the app runs `$EUKHE_BIN`, else `eukhe` beside the binary, else the one on `PATH`, as `eukhe --mode daemon` through `eukhe-client`'s launcher on Eukhe's socket (`$EUKHE_DAEMON_SOCKET`, else Eukhe's default). Use the binary of the Eukhe release pinned in the root `Cargo.toml` (`bundle.nu` fetches it).
- Python kernel: Eukhe runs it on one pinned CPython that it fetches itself (with its own uv) into `~/.eukhe/kernel/` the first time a kernel starts. The core runs `eukhe kernel install --check` at launch and, when it answers `not fetched`, `eukhe kernel install` in the background (needs network). Progress and failures (with Retry) show in a banner; Settings → General → Diagnostics → Python kernel shows the state and Install/Retry. `eukhe` finds `eukhe-runtime/` beside itself (Eukhe's release layout) or, run from an eukhe checkout's `target/`, in that checkout.
- Packaging: `nu bundle.nu [--profile debug|release]` (after `cargo build`) assembles `target/<profile>/bundle/` in Eukhe's release layout: `local-studio`, the release's `eukhe` (root `eukhe.nu`: fetched once into `target/eukhe/<tag>/` and checked against the release's `SHA256SUMS`, or `$EUKHE_BIN`), its sidecars (`eukhe-runtime/`, `skills/`, `models.bundled.json`, `mcp-services.bundled.json`, release exclusions), and `share/local-studio/` (`controller/`, and `skills/` as `app-skills/`). Run `bundle/local-studio` without `EUKHE_BIN`. A release bundle made in the dev shell gets the system's loader and no RUNPATH (`patchelf`), so it starts on a host without Nix and needs that host's libraries.
- Keybindings come from the core (`Update::Keybindings`, mapped in `src/bindings.rs`); `cmd` maps to Ctrl. Focus regions, recent-thread cycling and list keys live in `src/keyboard.rs`, the composer's vim engine in `src/vim.rs` (`Settings.vim_mode`). Composer and header choices use the shared popover in `src/picker.rs`, not GtkDropDown. Terminals live in the bottom drawer (`src/drawer.rs`) and run in the core (libghostty-vt): `src/terminal.rs` draws `Update::TerminalFrame` rows with Pango and sends keys (XKB hardware keycodes), mouse, scroll, paste and focus back through the core encoders. While a terminal has focus, app accelerators are suspended and the drawer takes Ctrl+Shift+T/D/E/W/C/V/A instead of the `terminalFocus` bindings.
- Providers (Settings → Providers, `src/providers.rs`) go through the core's providers service: keys with `set_provider_key`, custom endpoints with discovery and add/update/remove/refresh, fleet engines with `use_local_engine`. The Local page (`src/dashboard.rs`) watches the selected machine with `watch_local_dashboard` while it is visible; machine management lives in Settings → Local (`src/fleet.rs`).
- Client-only preferences (favorite editor, composer stash, sidebar width) live in `$XDG_CONFIG_HOME/local-studio/linux.ini` (`src/prefs.rs`); everything shared goes through core `Settings`, including custom themes (`Settings.custom_themes`, JSON).
- Colors come from `src/colors.rs`: the default palette (dashboards) and the built-in `gildrb` theme (dark and light, follows the color scheme). CSS, code highlighting (`src/highlight.rs`), diff tags and the terminal palette all read the current `Colors`; add new colored surfaces there, not as literals.
- Icons come from `src/icons.rs`: one Adwaita symbolic name per meaning (constants), 16 px (`icons::SIZE`), full foreground on interactive icons, hit targets of 24 px or more, and the icon CSS (plus a high-contrast sheet that drops all icon opacity). Icon-only buttons go through `icons::button`/`icons::flat`/`icons::describe`, which set the tooltip and the accessible label. Use only names shipped in the dev shell's `adwaita-icon-theme`.
- Assistant text and pull request bodies render through `src/markdown.rs`: one non-editable GtkTextView per text block (blocks are TextTags, code keeps the syntax tags, links open on click), cached per transcript item so streaming updates refill the same view. Ctrl+C copies exactly the visible selected text like macOS `MarkdownCopy`: list markers as shown (`•`, `1.`, nested items indented by tabs), code without fences or its language header, table cells separated by tabs, no `#`/`>`/`---` Markdown markers, a blank line between blocks.
- Headless runs use isolated state and a real local model named by `LOCAL_STUDIO_SMOKE_MODEL` (root `AGENTS.md`), never an Anthropic one and no linked credential. `--smoke` checks the empty-thread composer shows the daemon's default and fails if it is another model or thinking level:
  ```sh
  (umask 077 && mkdir -p /tmp/X/home /tmp/X/agent && cd /tmp/X/agent && echo '{}' > auth.json &&
    echo '{"defaultProvider":"ollama","defaultModel":"fv-smoke-lfm3-1.7b","defaultThinkingLevel":"off","retry":{"provider":{"streamIdleTimeoutMs":900000}}}' > settings.json &&
    echo '{"providers":{"ollama":{"baseUrl":"http://127.0.0.1:11434/v1","api":"openai-completions","apiKey":"none","models":[{"id":"fv-smoke-lfm3-1.7b","reasoning":false,"input":["text"],"contextWindow":32768,"maxTokens":8192,"cost":{"input":1,"output":1,"cacheRead":0,"cacheWrite":0}}]}}}' > models.json)
  env HOME=/tmp/X/home LOCAL_STUDIO_DATA_DIR=/tmp/X/data EUKHE_CODING_AGENT_DIR=/tmp/X/agent \
    EUKHE_DAEMON_SOCKET=/tmp/X/d.sock EUKHE_BIN=<eukhe> LOCAL_STUDIO_SMOKE_MODEL=ollama/fv-smoke-lfm3-1.7b \
    GDK_BACKEND=x11 GSK_RENDERER=cairo xvfb-run -a -s '-screen 0 1600x1000x24' dbus-run-session -- target/debug/local-studio --smoke
  ```
  - `scripts/tests/linux-smoke-test.sh <app> <eukhe> <new scratch dir>` runs `--smoke` that way (the model endpoint is `LOCAL_STUDIO_SMOKE_BASE_URL`), requires its hand-back lines and stops its daemon.
  - `--smoke`: adds a project, starts a supervised thread on the real model through the composer, approves its bash call, and requires the call's output and file (`smoke.txt`) plus the streamed reply in the timeline, then sends a follow-up (drawn at once as a local bubble, replaced by the core's user item, answered by the real model) and a send the core rejects (bubble removed, text back in the composer), then requires `@` to list a skill and a file, lists the project in the Files surface, runs a thread content search, types a command into a drawer terminal and waits for its output, and adds that output to the composer with Add to Chat. Then it checks Ctrl+T and vim `dw`/`dd`/`u` in the composer; prints `PASS linux smoke` and exits 0. It never writes `auth.json`. Set `SHELL` to bash for it. Use a GPU the model fits on (`ollama-window` on abbey1): the whole run has 300 s.
  - `--smoke-kernel [install|installed]`: run from `bundle.nu`'s bundle without `EUKHE_BIN`. `install` needs a fresh `HOME` (no `~/.eukhe/kernel/`): the launch must fetch the kernel, then a real `python` call ("list the files here and count them with Python") must succeed with no "not installed" error; `installed` on the same `HOME` must not fetch again and runs the same request. Prints `PASS linux smoke: kernel: …`.
  - `--smoke-providers`: with `LS_SMOKE_PROVIDER=http://127.0.0.1:<port>/v1` (the core's `provider_stub` example started with the key `smoke-key`) it discovers, adds and removes a custom endpoint through the endpoint dialog. It saves keys, so run it on a scratch agent dir with its own `auth.json` (`{}`) and `models.json` (`{"providers":{}}`), never a linked one; it needs no model login. Before anything starts it refuses (`FAIL`, exit 1) when `EUKHE_CODING_AGENT_DIR` is unset, its `auth.json` is a symlink, a hard link or holds keys, or the dir resolves into a real agent dir (`.pi`, `.eukhe`); it fails if any key is left in `auth.json` at the end.
  - `--snapshot <dir> [name-filter]`: renders every fixture scene (`fixtures::scenes()`: `src/fixtures.rs`, `src/scenes*.rs`, `src/dashboard_scenes.rs`, `src/keyboard.rs`) offscreen to `<dir>/<scene>.png`, open popovers included; needs no daemon. Look at the PNGs after UI changes. The `58-markdown-*` scenes (`src/markdown_scenes.rs`) show the Markdown cases and fail when `format::markdown` reads one wrong. `58-answer` lands a short answer and its end in one frame; any scene fails when an assistant text on screen has no height.
  - `LOCAL_STUDIO_SNAPSHOT_LIVE=1` adds the `usage-live*` scenes (`src/usage_scenes.rs`): they start the core against the daemon on `$EUKHE_DAEMON_SOCKET`, load the real usage report from its saved sessions and render the Usage page (30 days tokens and cost, 24 hours, gildrb, limits; dark and light). Point the daemon's `EUKHE_CODING_AGENT_DIR` at a scratch copy of the sessions.
  - `LOCAL_STUDIO_SNAPSHOT_LINK=<http url>` adds `link-app`, `link-system` and `link-app-off-thread`: each clicks a transcript link to that URL with Settings → Open links in set to Local Studio or the system browser. `link-app` fails unless the Browser panel opens and loads the URL; `link-system` fails if the panel opens; `link-app-off-thread` is set to Local Studio but clicks while the Usage page shows, and fails if the panel opens. The last two hand the URL to the system handler, so point `HOME` and the XDG dirs at a scratch dir whose `mimeapps.list` maps `x-scheme-handler/http` to a recorder.
  - Stop the daemon afterwards from the repo root: `cargo run --example smoke -p local-studio-core -- --stop /tmp/X/d.sock`.
- Never stop processes this app did not spawn.
