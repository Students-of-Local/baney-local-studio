# Local Studio

Native desktop clients for local LLM work. The agent core is [Eukhe](https://github.com/gildrb/eukhe); Local Studio adds native GUIs and the local-LLM fleet.

## Architecture

- Eukhe is the core, like libghostty is Ghostty's: sessions, durable storage, the harness, memory, tools and inference live there. Local Studio never reimplements them.
- The engine runs out of process as the Eukhe daemon (`eukhe --mode daemon`: supervisor + one worker per session), started through `eukhe-client`'s `ProcessLauncher` on Eukhe's socket path. GUIs reach it through the `eukhe-client` crate over the versioned `eukhe.daemon` protocol. A crash in the engine never takes a window down, and every Eukhe frontend can attach to the same session.
- Shared GUI logic lives once, in Rust (`core/`, crate `local-studio-core`): inbox across projects, transcripts, Local Studio state, git, files, terminals, usage, the Local fleet client, settings. Each GUI does only native chrome:
  - `macos/`: Swift + AppKit/SwiftUI, links the core through UniFFI (`kit/` → `LocalStudioKit`), like Ghostty links `GhosttyKit`.
  - `linux/`: Rust + GTK4 + libadwaita, links the core as a crate (own workspace, see `linux/AGENTS.md`).
- Core → GUI: `Studio` methods are fire-and-forget; the core calls `Waker.wake()` and the GUI drains `Studio.tick()` on its main thread into `Update`s.
- `controller/`: the local-LLM controller (Bun, port 18091): engine discovery, fleet gateway, registry launches. The core talks to it over HTTP and can start a bundled copy with its own data root.

## Rules

- Logic needed by both GUIs goes in `core/`; platform behavior (windows, menus, toolbars, notifications) stays in the GUI. Never port core logic into Swift or GTK code.
- Eukhe changes land in the eukhe repo, not as copies or patches here. Both workspaces pin `eukhe-client` and `eukhe-types` to one Eukhe release tag (git dependencies, root `Cargo.toml`); the apps bundle the `eukhe` binary of that same release (`eukhe.nu`: downloaded from the GitHub release and checked against its `SHA256SUMS` into `<target>/eukhe/<tag>/`, or `EUKHE_BIN=<eukhe built from the tag>`). Move both together.
- Verify end to end: build and run the real binaries. No new unit tests.
- Add no code comments.
- Never stop processes, controllers, engines, or GPU jobs this work did not start. Kill only PIDs you spawned.
- Controller: keep native inference requests as passthrough. Never disable CUDA graphs, enforce eager, or set output caps on vLLM/SGLang. New controllers use port 18091 and a separate data root.
- Never run against real user state in checks: isolate with `HOME`, `EUKHE_DAEMON_SOCKET`, `EUKHE_CODING_AGENT_DIR`, `LOCAL_STUDIO_DATA_DIR` under a scratch dir; stop the daemon after (`core` smoke example `--stop <socket>`).
- Checks drive a real model, never a faux one: a local model named by `LOCAL_STUDIO_SMOKE_MODEL=<provider>/<model>` (the gate uses `ollama/fv-smoke-lfm3-1.7b` on abbey1's Ollama), a handful of short prompts per run, one run at a time. Never an Anthropic model through Eukhe: its subscription sign-in is ruled out (Donovan, 2026-11-17) and API keys are paid billing. The core examples write their own scratch `models.json` (that one keyless provider at `LOCAL_STUDIO_SMOKE_BASE_URL`, default `http://127.0.0.1:11434/v1`, with a real context window), `settings.json` and an `auth.json` of `{}`, all mode 0600, and link no credential. On abbey1 claim the shared GPU first (`~/.local/bin/ollama-window wait <minutes> <model> <who>`, then `release <who>`); `scripts/e2e.sh` does this itself. Assert behavior a correct app always shows (a real tool call and its file, the reply arriving, transcript order, usage with real tokens and cost), never model wording. docs/e2e.md has the model choice and the daily timer. `claude_signin_smoke` drives no model at all: it checks that Claude sign-in threads are refused before any model is asked.
- `macos/AGENTS.md` and `linux/AGENTS.md` hold the per-platform build and lint rules.

## Commands

- Core: `cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings`
- Core end to end (each takes the release `eukhe` binary, e.g. `target/eukhe/<tag>/eukhe` after an app build, needs `LOCAL_STUDIO_SMOKE_MODEL`, ends with a usage report that must count real tokens and cost): `cargo run -p local-studio-core --example smoke -- <eukhe> <scratch>`, `--example workspace_smoke -- <eukhe> <scratch>`, `--example working_smoke -- <eukhe> <scratch>` (a tool step keeps the thread busy with one start time)
- Providers end to end: `cargo build -p local-studio-core --examples`, then `providers_smoke <eukhe> <scratch>` from the examples dir; it round-trips the local model's keyless provider (listed as needing no key), starts the `provider_stub` example (the custom endpoint under test) on a random 127.0.0.1 port, round-trips a custom endpoint through Eukhe on its own scratch `auth.json` (`{}`) — refusing to start (`local_studio_core::check_scratch_agent`) if that file is a symlink, a hard link or holds keys, or the dir resolves into a real agent dir (`.pi`, `.eukhe`) — checks models.json and auth.json return to the providers they started with, and stops the stub by PID
- Claude sign-in end to end: `--example claude_signin_smoke -- <eukhe> <scratch>` is the one check that drives no model, because it tests a refusal: a prompt that reached a model would be the failure. It needs no model login and never starts `claude` or `codex`; on scratch agent dirs (`HOME` under the scratch too) it writes an `auth.json` marking `anthropic` as `oauth` with empty tokens, plus a keyless `smoke-stub` endpoint on a closed 127.0.0.1 port, and requires no Eukhe `anthropic` model listed, the Claude Code models still listed, the providers line pointing to Claude Code, the Anthropic row not ready, and refusals with that line for an Eukhe `anthropic` thread, a thread with no provider while Eukhe's `settings.json` default is `anthropic`, an `anthropic` thread in a new worktree (no `local-studio/*` branch or worktree left), title generation and a generated commit message on `anthropic`, while a thread in a project whose `.eukhe/settings.json` default is the stub must start; then a fake `anthropic` API key must list its models as configured with no such line, start two `anthropic` threads with no prompt sent, and after `auth.json` switches to `oauth` a send and a fork on the first must be refused, and a send on the second must be refused from a second Studio on the same data dir, once with the daemon kept and once with it stopped; then, with the global default on the stub and a project `.eukhe/settings.json` default of `anthropic`, a thread with no provider there must be refused locally and in a new worktree, leaving no branch, worktree or prompt in any session. Keep `<scratch>` short (default `/tmp/ls-signin`): Eukhe puts session lock sockets under the agent dir, within 103 bytes. It stops each daemon it started
- Durability end to end: `--example durable_smoke -- <eukhe> <scratch>` quits the core mid-turn (a real `sleep 8` bash call), checks the Eukhe daemon survives, and requires the reopened core to show the turn's tool output and reply
- Sidebar order end to end: `--example order_smoke -- <eukhe> <scratch>` runs a slow tool turn and a quick turn, then across two core restarts, a rename and opening each thread requires the order to stay by last user message (never by later writes), and a new user message to move its thread to the top
- Stuck-thread end to end: `--example stuck_smoke -- <eukhe> <scratch>` keeps one short real turn for the usage report, then runs a real `sleep 90` bash step three times: Stop must take the thread out of Working within 20 s (the daemon agreeing) and Delete must then remove it; after a SIGKILL of the session worker (a child of the smoke's own daemon, checked before the kill) the row must agree with the daemon's own view of the run within 45 s, Stop must then end it within 20 s and Delete remove it; Delete on a running thread must stop and remove it
- Local page end to end: `cargo build -p local-studio-core --examples`, then `local_smoke <eukhe> <scratch> <bind ip> <host name>` with port 18091 free and `bun` on `PATH`; it starts the core's bundled controller on a scratch data root (every port already listening excluded), a stub engine on 127.0.0.1 and a stub custom endpoint on `<bind ip>` reached as `<host name>`, then makes both slow (4 s), silent (15 s), recover and go away, printing each snapshot and requiring loaded → loaded → stale → unreachable → loaded → no model loaded (with a link to the other engine) → unreachable. `LOCAL_SMOKE_BASE`, `LOCAL_SMOKE_MODEL` and `LOCAL_SMOKE_API_KEY` (an `apiKey` value as in `models.json`, such as `!cat <key file>`) add a real custom endpoint, read with that key
- Phone server end to end: `cargo build -p local-studio-remote --bins --examples`, then `remote_smoke <eukhe> <scratch>` from the examples dir; it starts `local-studio-serve` on a scratch data dir and, as real WebSocket phones, pairs through XXpsk3 (stale, wrong and burned secrets are refused), reconnects through KK with a delta or snapshot resume, refuses headers outside protocol 2 with `incompatible`, checks the close codes, limits and bans, blob uploads both ways, per-phone request ids, a watch that resumes before the core knows its thread, and refusal of a revoked device, a foreign `Host` and a mismatched `Origin`; its model stage runs a real bash write, checks transcript inserts reach only the watching phone, a retried send that runs once, a follow-up queued behind a real `sleep` that runs after it, a supervised approval answered from the phone that writes its file, and the notify webhook. its model stage still takes `LOCAL_STUDIO_SMOKE_AGENT` and `REMOTE_SMOKE_MODEL`: under the rule above, point them at a scratch agent dir holding a local-model `models.json` and that model, never `$HOME/.eukhe` or an Anthropic model (moving it to `LOCAL_STUDIO_SMOKE_MODEL` is the Remote lead's follow-up); it prints hello and send-to-first-update latency, ends with the usage report, and stops serve and its daemon by PID
- Desktop links end to end: `cargo build -p local-studio-remote --bins --examples`, then `link_smoke <eukhe> <scratch>` from the examples dir with a short scratch path (the daemon sockets live under it); machine A's thread runs the real `claude` binary (`claude-code`/`haiku`) with its own sign-in and `HOME` unchanged, and desktop B (an in-process core on its own scratch data dir and daemon) pairs with `local-studio-serve` on desktop A's scratch data dir through a pasted link, then checks the machine row, A's project and thread rows under `@<machine>/` ids, `links.json` at 0600 in a 0700 folder, a remote `start_thread`, watch and reply stream, a queued follow-up, a supervised approval answered from B, the notice for an op a link does not carry, a SIGSTOP of serve that must end the link within the 50 s silence limit and fail a request sent during it as disconnected, a fake far side on A's port whose `daemon` and `settings` updates must not reach B while its notice does, reconnect through a snapshot after serve is killed and restarted, `pair_again` after `revoke --all` and `forget_machine` removing the rows; A's own core must show the same transcript. It prints pair, reconnect and send-to-first-update latency, ends with A's usage report counting `claude-code` tokens, and stops serve and both daemons by PID
- Hosted tunnel client end to end: `cargo build -p local-studio-core --bin local-studio`, then in a baney75/local-studio-tunnels checkout `cd worker && npm ci && LS_DEVICE_BIN=<target>/debug/local-studio npm run e2e:device`; it runs both service Workers under `wrangler dev` on the stand-in and drives `local-studio tunnel` request, up, down, revoke and release with a fake cloudflared through `LS_CLOUDFLARED` (docs/INTERFACE.md there), then on a second device the token fetch backoff after cloudflared fails to authenticate, `tunnel ports` and the route record. Put a fake `local-studio-serve` first on `PATH` to see `up` call `allow-tunnel-host`. The pinned cloudflared download runs on its own: `local-studio tunnel cloudflared --yes` with `HOME`, `LOCAL_STUDIO_DATA_DIR` and `TYCHICUS_CONFIG_DIR` in a scratch dir
- Tunnel setup end to end: `cargo build -p local-studio-core --bin local-studio --example tunnel_setup_smoke`, then `<target>/debug/examples/tunnel_setup_smoke <target>/debug/local-studio <scratch>`. It runs the binary with `HOME`, `LOCAL_STUDIO_DATA_DIR` and `TYCHICUS_CONFIG_DIR` in the scratch dir and every outside program replaced by a shell shim that logs its argv (`LS_CLOUDFLARED`, `LS_LAUNCHCTL`, `LS_SYSTEMCTL`, `LS_TAILSCALE`, `LS_TYCHICUS`, `LS_SERVE_BIN`), and points the public checks at its own stub with `LS_TUNNEL_CHECK_URL`. It drives `setup --cloudflare` (needs_signin without cert.pem, then ready: create, route dns for the hostname and alias, service install and start, allow-tunnel-host, again without a second create), `setup --tailnet` (needs_signin; a path already served elsewhere refused; `needs_serve_allow_host` with route.json written when the serve shim has no `allow-host`; then ready with exactly the eleven set-path calls at their ports, `local-studio-serve allow-host`, and never Funnel or `allow-tunnel-host`), `adopt` (confirm changes nothing; `--yes` stops Tychicus's service only after Local Studio's runs and both names answer, then joins), adopt rolling back when the new service won't start and when the route fails after Tychicus stopped, and `off` after each. It first checks that the binary refuses the real launchctl or systemctl with the scratch `HOME` (`unsafe_service_path`), and ends by checking that every plist and unit it saw stayed under the scratch `HOME`. It never touches the real launchd, systemd, Tailscale or Cloudflare. It checks that the yml holds exactly the eleven anchored paths per hostname at their ports and one final 404, that route.json has its exact shape at mode 0600 in a 0700 folder, and that a bad hostname is refused touching nothing. Run it a second time against a `LOCAL_STUDIO_CHANNEL=stable` build (its own `CARGO_TARGET_DIR`): it then expects `waitlist` from setup, adopt, request and status, `off` from off, and no shim call
- Harness end to end: `--example harness_claude_smoke -- <eukhe> <scratch>` and `--example harness_codex_smoke -- <eukhe> <scratch>` run a thread on the real `claude` or `codex` CLI with its own sign-in (`HOME` stays unchanged): reply, approvals denied and approved, abort, restart, resume and usage; a step that expects no approval denies any card it gets and keeps going, and a timeout names any card still pending; the Claude one also lists commands and skills with that thread focused (`scripts/tests/harness-resources-test.sh <binary> <eukhe> <scratch>`)
- Harness queue and restart paths, no sign-in: `cargo build -p local-studio-core --examples`, then `harness_queue_smoke <eukhe> <scratch>` from the examples dir. The `fake_claude` and `fake_codex` examples stand in for the CLIs (scripted by words in the prompt: `slow`, `lag`, `quota`, `quota-error`, `quota-fail`, `limit`, `exit`, `reject`, `discard`, `crash`, `skill`; `limit` hits a usage limit with a reset time only while the account dir holds a `limited` file), the one exception to real-model checks, because an account stop or a CLI exit cannot be caused on demand. It checks a message sent during the turn that changed the Claude Code effort is answered and the next send runs at the new effort, an account stop after that change still shows its error and Failed notification, a Stop whose held message the CLI drops still lets the new effort apply, and that Codex held messages wait for a pending start, survive a refused start, and are shown when an exit (even during their start) or account stop drops them, and that a Supervised Codex turn asking an approval no step expects is denied through the harness smokes' shared step loop and goes on. Its account stage lists two scratch accounts per CLI under the scratch `HOME` and, for Claude Code and Codex each, requires a `limit` turn on the limited first account to be answered on the second with the switch notice, the thread's account and session file moved, and no Failed notification, a new thread to start on the second account, and with both limited the error and Failed notification to name the reset (`scripts/tests/account-switch-test.sh <harness_queue_smoke binary> <eukhe> <scratch>`)
- Plugin permissions end to end: `cargo build -p local-studio-core --bin local-studio --examples --features test-hooks`, then `scripts/tests/plugin-grants-test.sh <target>/debug/local-studio <scratch>` (it drives `consent_driver` from the examples dir, including its `plugins <id>:<capability>=on|off ...` mode for the Settings, Plugins switches) and `granted_smoke <eukhe> <scratch>` from the examples dir: a plugin asking `mcp-server`, `screen-capture` and `site-secrets` with only `mcp-server` granted must be ready, each real-model thread runs, and its server, started from the `settings.json` entry the core wrote (command, args, cwd and env references resolved; Eukhe starts MCP servers lazily, so the smoke does not wait on that), must see no `LOCAL_STUDIO_GRANTED_*` variable, then after its Settings switch turns `screen-capture` on (then off) exactly `LOCAL_STUDIO_GRANTED_SCREEN_CAPTURE` (then none); it ends with the usage report and stops its daemon
- Stop a scratch daemon: `cargo run -p local-studio-core --example smoke -- --stop <socket>`
- Controller: `cd controller && bun install && bun run typecheck && bun run test`
- Share one cargo target across worktrees: `CARGO_TARGET_DIR=/tmp/ls-cargo-target`
- Local CI, for when GitHub Actions starts no run: `nu scripts/local-ci.nu <pr> --post` from a checkout runs every Linux job in `.github/workflows/ci.yml` on the PR's head, each in a fresh worktree, and posts a `local/<job name>` commit status for each. It runs only the owner's own branches. It needs the zig and nu versions CI pins, on `PATH` or in `~/.local/opt/<tool>-<version>/` (chapel1 has both); without nix it builds the Linux app against the host's GTK libraries and adds the flake's zig. Logs land in `~/.local/state/local-ci/<sha>/`. Merge on them with `merge_green.py --check 'local/Core (Linux)' --check 'local/Linux app' --check 'local/Channels'`
